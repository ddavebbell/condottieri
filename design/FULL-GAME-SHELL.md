## What this task is

The game today is a working prototype: one board, a list of 13 maps, a rules
page, and a pop-up before and after each mission. The rules are finished and
tested. **Your job is to build everything around the board** so it feels like a
finished phone game: title screen, sign-in screen, campaign map, mission
briefing, a proper in-game screen, results, and settings, all with saved
progress.

**You are not changing how the game plays.** No rule, map or piece behaviour
changes in this task.

## Ground rules (do not break)

1. **Edit `prototype/src/`, never `prototype/dist.html`.** `dist.html` is generated by
   `node tools/build.js`.
2. **Do not touch the rules.** `src/engine.js` is shared with the solver. The only
   allowed change there is none. If you believe you need one, stop and ask.
3. **After every milestone:** run `node tools/build.js` and `node test/rules.test.js`.
   All 29 tests must pass. Commit with a clear message.
4. **One self-contained HTML file.** Everything (code, CSS, images, font) stays
   inlined in `dist.html`. No external requests, no CDN, no npm runtime
   libraries. Plain JavaScript and CSS, matching the existing code style.
5. **Phone first.** Design for a portrait phone (~390×844) and check at 360px
   wide. Everything must be reachable with a thumb. Desktop just centres the
   phone layout.
6. **Keep the file small.** The current build is ~360 KB. Stay under 600 KB.
   Reuse the art already embedded in `shell.head.html` rather than adding new
   copies.
7. **The board must behave exactly as it does now.** Every existing control
   (end turn, undo, restart, hint, threat toggle, faces toggle, texture setting,
   captured list, rules guide) must still work, just moved to its new home.

## How the code is put together

- `src/shell.head.html`: all CSS, embedded art (tiles, pieces, BLACKCASTLE font,
  landscape image) and the page HTML.
- `src/engine.js`: rules. Don't touch.
- `src/maps.part.js`: map data, injected into the engine by the build.
- `src/ui.part.js`: draws the board, handles taps, the rules page and overlays.
- `tools/build.js`: glues them into `dist.html`.

**Add a new file `src/screens.part.js`** for the screen system and navigation,
and add it to `tools/build.js` so it's bundled **after** `ui.part.js`. Keep
`ui.part.js` focused on the board. Move code out of it only where the shell
needs to call it (for example, a clean `startMission(index)` function and an
`onMissionEnd(result)` hook).

## Screens and flow

```
Title ──► Sign in ──► Campaign map ──► Briefing ──► Battle ──► Result
  │          (first launch only)          ▲                      │
  └──► Settings                           └──────────────────────┘
```

Build a tiny screen router: one screen visible at a time, a slide or fade of
~200ms between them, and the phone/browser Back button goes to the previous
screen (use `history.pushState`; Back from Battle opens the pause menu instead
of leaving).

### 1. Title
- Full-bleed landscape art (already embedded), darkened at the bottom.
- "CONDOTTIERI" in BLACKCASTLE, large.
- Buttons: **Continue** (only if a save exists; resumes at the campaign map),
  **New campaign** (confirms before wiping a save), **Settings**.
- Small version number at the bottom.

### 2. Sign in
Shown on first launch, and reachable from Settings.
- **Real accounts are out of scope for this task.** They need a server, which
  this game doesn't have.
- Build the screen fully, with a name field ("What do they call you,
  Captain?") and a **Continue as guest** button that works: it stores the name
  locally.
- ~~Include **Sign in** and **Create account** buttons shown as disabled~~
  **Changed 2026-09-25:** one **Sign in with Google** button, live when the page
  is served by the Worker and hidden when opened as a file.
- Put all save/load behind two functions (`loadProfile()`, `saveProfile()`), so
  swapping local storage for a server later touches one place.

### 3. Campaign map
- A parchment map of northern Italy, drawn in CSS and inline SVG: aged-paper
  background, ink coastline and rivers, a compass rose. No new raster images.
- The 13 missions are stops along a dotted route, in the order they appear in
  `MAPS`. Each stop is a wax-seal style marker:
  - locked: grey, not tappable
  - available: faction red, gently pulsing
  - won: gold seal
  - won with no men lost: gold seal with a laurel mark
- Missions unlock one at a time as the previous one is won.
- Header: the player's name, "Contracts fulfilled: X / 13".
- A **debug unlock**: tapping the title 5 times unlocks every mission. I need
  this for testing; keep it.

### 4. Briefing
- Mission name in BLACKCASTLE.
- `brief` / `problem` as the letter from the employer, set like a letter on
  parchment.
- "Objective" line (reuse the existing objective text function).
- "This contract teaches:" + `teaches`.
- A small preview of the board (reuse the rules-page mini-board style).
- Buttons: **Accept contract** (starts the battle) and **Back**.
- This replaces the current pre-mission overlay.

### 5. Battle
- The existing board, centred and as large as fits, framed like a painted
  board on a war-table (a dark wood border in CSS).
- Top bar: mission name, turn "4 / 12", whose move it is, and a **menu button**.
- Bottom bar (thumb zone): **End turn**, **Undo**, **Hint**.
- The message log stays, as one line under the board.
- Captured pieces move into a small strip, one for each side.
- **Pause menu** (menu button or Back): Resume, Restart, Rules guide, Settings,
  Abandon contract (back to the campaign map, with confirmation).
- The threat and faces toggles and the texture setting move into Settings. They
  must keep working and keep their current defaults.

### 6. Result
- Replaces the current end-of-mission overlay.
- Won: "Contract fulfilled", a gold seal, men lost count, turns used, and the
  laurel if no men were lost. Buttons: **Next contract**, **Campaign map**.
- Lost: "Contract failed", the reason (existing `state.reason`). Buttons:
  **Try again**, **Campaign map**.
- Save progress **before** showing this screen.

### 7. Settings
Reachable from Title and the pause menu.
- Texture strength (the existing Full / Muted / Faint / Flat)
- Show threats (existing toggle)
- Show protection glow (existing "faces" toggle)
- Sound on/off (store the setting only; there is no sound yet)
- Player name (edit), and "Sign in" (goes to the Sign in screen)
- Rules guide (opens the existing rules page)
- Reset progress (with confirmation)
- Save settings immediately when changed.

## Saving

- Use `localStorage` under one key, `condottieri.save.v1`, holding JSON:
  ```json
  { "profile": { "name": "Dave" },
    "settings": { "tex": 0.5, "threat": true, "faces": true, "sound": true },
    "progress": { "0": { "won": true, "flawless": true, "bestTurns": 7 } } }
  ```
- Key progress by the map's index **and** store its `name`, so reordering maps
  later can be migrated.
- Wrap every read and write in `try/catch`. If storage is unavailable or the
  save is broken, the game must still start (as a fresh player), never crash.
- A mission counts as flawless if the player lost no pieces. Use the existing
  captured-pieces data; don't add rules to work it out.

## Look and feel

Follow the art direction in the GDD: Renaissance woodcut and fresco, aged paper,
muted earth palette, with the two faction colours as the only strong colour.

- **Type:** BLACKCASTLE for titles and mission names only. A plain serif stack
  (`Georgia, "Times New Roman", serif`) for body text. The existing sans for
  small UI numbers is fine.
- **Colours:** reuse the CSS variables already in `shell.head.html` (`--rosso`,
  `--gold`, `--ink`, `--text`, etc.). Add parchment tones as new variables:
  `--parchment: #e9dcc0; --parchment-dark: #cdb98f; --ink-brown: #3b2a1a;`
- **Buttons:** look like stamped wooden or leather plaques: a solid fill, a
  thin darker border, a slight inner shadow, and pressed down on tap. Minimum
  48px tall.
- **Motion:** small and quick. Screen fades ~200ms, the available seal pulses.
  Respect `prefers-reduced-motion`.
- **Safe areas:** keep content clear of the phone notch and home bar with
  `env(safe-area-inset-*)`.
